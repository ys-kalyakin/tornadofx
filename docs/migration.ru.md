# Миграция с 1.7.20

Этот форк обновляет фреймворк до современного Java-стека — сознательный разрыв
совместимости с релизом 1.7.20. Потребителям, которые не готовы к миграции,
следует оставаться на 1.7.20. Каждое breaking change ниже зеркалит
[журнал изменений проекта](https://github.com/ys-kalyakin/tornadofx/blob/master/CHANGELOG.md).

## Базовая платформа

- Фреймворк собирается тулчейном **JDK 21**, компилируется против
  **OpenJFX 21** (объявляется как Maven-зависимости с платформенными
  классификаторами) и публикуется как **байткод Java 17**.
- **Поддержка JavaFX 8 / JDK 8 прекращена**: нужен рантайм JDK 17+ с JavaFX 21
  в classpath. Полагаться на JavaFX, встроенный в JDK, больше нельзя —
  подключите используемые модули `org.openjfx` (см.
  [Начало работы](getting-started.md#maven)).

## Kotlin 2.x (K2)

- Фреймворк собран Kotlin 2 с `jvmTarget` 17.
- Потребители должны собирать свои проекты **Kotlin 2.3 или новее** с
  `jvmTarget` 17: фреймворк содержит метаданные Kotlin 2.4.0, а компилятор
  Kotlin читает метаданные максимум на одну минорную версию вперёд.
- Обновите плагин Kotlin в IDE, настройте `jvmTarget = "17"` в Maven/Gradle и
  после обновления сделайте полную пересборку (если что-то не инлайнится —
  очистите кэши и перезапустите IDEA).

## REST-клиент перенесён на HttpClient 5

- `Rest` перенесён с Apache HttpClient 4 на **HttpClient 5**
  (`org.apache.httpcomponents.client5:httpclient5`, scope `provided` —
  объявите эту зависимость в приложении, если используете Apache-движок).
- Публичные классы `HttpClientEngine`, `HttpClientRequest` и
  `HttpClientResponse` теперь выставляют **типы client5** — код, работавший с
  типами client4, должен перейти на соответствующие классы
  `org.apache.hc.client5`.
- Basic auth применяется **превентивно** через `AuthContext`: HttpClient 5.6
  больше не поддерживает старый превентивный рецепт с authCache, поэтому
  установка учётных данных через `setBasicAuth()` работает без round-trip на
  challenge.
- Digest-`AuthContext` теперь работает и для Apache-движка.
- Таймауты на уровне запроса задаются через
  `request.properties["tornadofx.requestTimeoutMs"]`
  ([REST-клиент](rest.md)).

## Поддержка OSGi удалена

- Пакет `tornadofx.osgi`, зависимость Felix, конфигурация манифеста бандла и
  `FX.osgiDebuggerShortcut` удалены.
- `FX.osgiAvailable` помечен deprecated и всегда возвращает `false`.
- **Потребителям OSGi следует оставаться на ветке 1.7.x** (1.7.20).

## URL-обработчик стилей перенесён

- Обработчик URL типобезопасных стилей переехал из `sun.net.www.protocol.css`
  в **`tornadofx.css`**. Фреймворк регистрирует его автоматически; обновиться
  должны только приложения, которые обращались к старому пакету напрямую.

## Типы фасадов ViewModel.bind под Kotlin 2

- С более точным выводом типов в K2 привязка producer'а, возвращающего
  `ObjectProperty`, даёт **объектный фасад** (соответствующий выведенному
  типу результата) вместо типизированного фасада. Код, полагавшийся на
  типизированный фасад такой привязки, должен адаптироваться (используйте
  перегрузку `bind` с типизированным свойством).

## Оставайтесь на 1.7.20, если...

- Вы разворачиваете OSGi-бандлы.
- Вы не можете перейти на рантайм JDK 17+ или JavaFX 21.
- Вы не можете поднять компилятор Kotlin до 2.3+.

Документация upstream-ветки 1.7.x — оригинальная
[вики TornadoFX](https://github.com/edvin/tornadofx/wiki).
