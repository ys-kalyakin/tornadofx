# EventBus

EventBus позволяет компонентам общаться без прямых ссылок друг на друга.
События — типизированные классы данных; подписки объявляют, в каком потоке
выполняются.

## Определение и отправка события

```kotlin
import tornadofx.FXEvent

class CustomerSelected(val customer: Customer) : FXEvent()

// отправить откуда угодно
fire(CustomerSelected(customer))
```

## Подписка

Внутри любого компонента (View, Controller, Fragment, App):

```kotlin
class DetailsView : View() {
    init {
        subscribe<CustomerSelected> {
            show(it.customer)
        }
    }
}
```

Подписки привязаны к жизненному циклу компонента — они снимаются при
уничтожении компонента, поэтому ручного учёта подписок, склонного к утечкам,
нет.

## Выбор потока

Каждый тип события объявляет поток, в котором выполняются подписчики. По
умолчанию это поток JavaFX Application — событие можно отправить из любого
потока, а подписчики всегда видят его в UI-потоке:

```kotlin
class DataRefreshed(val rows: List<Row>) : FXEvent()
```

События с доставкой в фоновый поток выполняют подписчиков в worker-потоке —
удобно для логирования, записи в БД и другой работы вне UI:

```kotlin
import tornadofx.EventBus.RunOn

class AuditLogged(val entry: String) : FXEvent(runOn = RunOn.BackgroundThread)
```

## Скоупы

События можно отправлять в конкретный `Scope`, чтобы компоненты из разных
скоупов не получали чужие события: `fire(event, scope)`. События без скоупа
доставляются во все скоупы.

## Когда использовать EventBus

- Развязка View от Controller (и друг от друга)
- Уведомления «один — многим» (например, «данные изменились» всем открытым View)
- Коммуникация между скоупами без синглтонов

Для потоков «запрос/ответ» внутри одного экрана предпочтительнее прямое
внедрение ([View и DI](views.md)) — шина раскрывается на семантике
широковещательных событий.
